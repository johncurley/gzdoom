KEY ARCHITECTURAL PATTERNS
===========================

1. MANAGER FACTORY PATTERN
   - VulkanRenderDevice owns all subsystem managers
   - Single instance per renderer
   - Managers store back-reference: VulkanRenderDevice* fb

2. LAZY EVALUATION
   - State changes queued, applied when needed
   - Apply() method batches pending changes
   - Reduces command buffer recording overhead

3. RING BUFFER PATTERN
   - Circular allocation for dynamic per-draw data
   - MatrixBuffer: model/texture matrices
   - StreamBuffer: per-vertex data
   - Avoids GPU stalls through wrapping

4. DESCRIPTOR SET POOLING
   - Multiple pools with lazy expansion
   - Backpressure: GPU stall if pool exhausted
   - Deferred deletion: freed after GPU finishes

5. PIPELINE CACHING
   - Lazy compilation on first use
   - Cached in std::map<VkPipelineKey, VulkanPipeline*>
   - Persistent disk cache across runs

6. DEFERRED DELETION
   - GPU resources queued for deletion
   - Freed only after GPU finishes processing
   - Prevents use-after-free, GPU stalls

7. DYNAMIC DESCRIPTOR OFFSETS
   - Avoids rebinding descriptor sets
   - Three dynamic offsets for HW buffers
   - Per-draw offset updates only

CRITICAL COMPONENTS
====================

VulkanRenderDevice
  - Constructor: Creates VulkanDevice with surface
  - InitializeState: Creates 12 subsystems in specific order
  - Update: Per-frame flow coordination
  - Accessors: Get* methods for all managers
  - Factory methods: CreateHardwareTexture, CreateMaterial, etc.

VkRenderState (606 lines - MOST CRITICAL)
  - Manages ALL GPU render state
  - Lazy state tracking and application
  - Apply() method: Core rendering logic
  - ApplyStreamData, ApplyMatrices, ApplyRenderPass
  - ApplyScissor, ApplyViewport, ApplyPushConstants
  - ApplyVertexBuffers, ApplyMaterial, ApplyHWBufferSet
  - VkRenderStateMolten variant for macOS

VkCommandBufferManager
  - Dual command buffers: transfer + graphics
  - Circular queue of 8 concurrent submits
  - Fence/semaphore synchronization
  - Deferred deletion lists
  - BeginFrame, FlushCommands, WaitForCommands

VkRenderPassManager
  - Pipeline creation and caching
  - Render pass object management
  - VkPipelineKey: 13 components identify unique pipeline
  - VkRenderPassKey: 4 components identify render pass
  - Lazy pipeline compilation

VkDescriptorSetManager
  - Three-tier resource binding:
    - Set 0 (Fixed): Shadowmap, Lightmap, RTX
    - Set 1 (HW Buffers): UBO/SSBO with dynamic offsets
    - Set 2 (Material): Texture layers (variable count)
  - Per-frame updates to fixed/HW buffer sets
  - Material descriptor set caching

VkBufferManager
  - Creates vertex, index, data buffers
  - Ring buffers: MatrixBuffer, StreamBuffer
  - Special buffers: ViewpointUBO, LightBufferSSO, BoneBufferSSO
  - FanToTrisIndexBuffer for topology conversion

VkShaderManager
  - Incremental shader compilation
  - Four compile states:
    - State 0: Material shaders
    - State 1: NAT (no alpha test) variants
    - State 2: User custom shaders
    - State 3: Effect shaders
  - Per-pass-type compilation

PERFORMANCE OPTIMIZATIONS
==========================

1. Batched Submissions
   - Flush every 1000 draw calls (vk_submit_size)
   - Reduces submission overhead

2. Dynamic Offsets
   - Avoids descriptor set rebinding
   - 3 dynamic offsets per draw

3. Pipeline Caching
   - Persistent disk cache
   - Lazy compilation on first use

4. Ring Buffers
   - Circular allocation
   - Avoids GPU stalls

5. Deferred Deletion
   - Prevents GPU stalls on destruction
   - Freed after GPU finishes

6. MSAA Support
   - Configurable sample counts
   - VkSampleCountFlagBits tracking

METAL IMPLEMENTATION STRATEGY
=============================

Class Mapping:
VulkanRenderDevice → MetalRenderDevice
VkRenderState → MetRenderState
VkCommandBufferManager → MetCommandBufferManager
VkRenderPassManager → MetPipelineManager
VkDescriptorSetManager → MetArgumentBufferManager
VkBufferManager → MetBufferManager
VkShaderManager → MetShaderManager
VkSamplerManager → MetSamplerManager
VkTextureManager → MetTextureManager

Keep Same Patterns:
├─ Manager factory architecture
├─ Lazy state application
├─ Ring buffer patterns
├─ Three-tier binding strategy
├─ Deferred resource cleanup
└─ MSAA support

Adapt for Metal:
├─ Use immediate encoding (vs. deferred recording)
├─ MTLArgumentBuffer (vs. descriptor sets)
├─ MTLRenderPipelineState (vs. VkPipeline)
├─ MTLRenderPassDescriptor per operation
├─ Command buffer completion handlers (vs. fences)
└─ Autoreleasepool for timing deletions
