THE STANDING LIST
================================================================================

1. AO COMPOSITE — root-caused, fixed, UNVERIFIED AT RUNTIME. See (0) above.

   depthblur.fp's VERTICAL pass wrote 0.0 into the depth channel while the
   horizontal pass preserved it. ssaocombine.fp derives its whole output alpha
   from that channel twice over — depthSignal = 1 - exp2(-ssao.y * 0.01)
   collapses to 0, and the ssao.y > 2.0 gate fails — so the alpha blend was an
   exact no-op. AO was computed correctly and multiplied by zero.

   Measured, not inferred (mt_ao_probe):
       mean ssao.x = 0.86671   <- real occlusion; AO generation was never wrong
       max  ssao.y = 0.000     <- depth channel dead
       gate passes 0 / 278640 px
       SceneColor differing px = 0 / 1113120 across the composite draw

   Fixed in ebc854ebf by preserving centerDepth. NOT a Metal bug: both shaders
   are shared, so GL and Vulkan had it too, from 595ffaf0f. master is unaffected
   — it composites vec4(fogColor, 1.0 - attenutation) with no depth dependency
   at all, so there is nothing to report upstream.

   DECISION: the depth dependency was KEPT rather than reverted to master's
   line. That means AO carries a near-field falloff — depthMask is ~0.29 at 50
   world units, ~0.9 by 400 — so expect weaker close-range AO than stock GZDoom.
   Intended, not a regression. Record any future "AO looks weak up close"
   against this line.

2. STRING PATCHES — CLOSED (91d6e7213). Was "one is silently dead"; the audit
   found five plus a function that could never run. PatchFragmentShader deleted
   (unreachable by construction — it dispatched on names no stock shader has,
   and could only ever fire on a MOD shader whose filename contained "main" or
   "ssao", silently rewriting it). vNormal patch deleted (zero matches).
   ssaocombine alpha patch removed rather than re-derived: it discarded fogColor
   and its *1.85 was tuned against a composite that contributed nothing.
   Sky-dome guard re-derived and re-anchored. Everything surviving now warns
   once per run on a miss or an unexpected match count.

3. STILL OPEN, UNCHANGED: Tier 2 direct-composite path has never executed ·
   Apple Silicon completely untested (nothing on the compute path has ever run
   there — not performance, not the read-write paths) · BlitCurrentToImage's
   conversion branch confirmed unreachable, kept deliberately, its V-flip
   unverified · custom PP shaders never tested, no mod to hand.

THE COVERAGE HOLE — still the durable finding
================================================================================

This branch is validated by "build it, load a WAD, look at it", so the tested
surface equals exactly whatever the dev config happens to enable. Passes behind
a default-off cvar had never had a single pixel checked. Four were broken.

Assume every default-off postprocess setting is untested until someone turns it
on and looks.

  pass        gate                     default        draws  status
  present     always                   on             1      exercised constantly
  exposure    with bloom               off (fresh)    many    on in this ini
  bloom       gl_bloom                 false          many    on in this ini; sub-1%
  tonemap     gl_tonemap               0 = off        1      WAS BROKEN -> fixed
  lens        gl_lens                  false          1      WAS BROKEN -> fixed
  fxaa        gl_fxaa                  0 = off        2      UNRESOLVED, test (c)
  ssao        gl_ssao                  0 = off        many   FIXED, verify with (0)
  colormap    GAMEPLAY (fixedcm/flash) fires in play  1      NEVER TESTED, test (b)
  menu blur   gl_menu_blur / gameinfo  -1 = mod's     many   runs, output sane
  custom PP   gl_custompost + a mod    true           N      NEVER TESTED

"Default" means "in this ini" for bloom, exposure and ssao; in a FRESH config
only present runs. Cvar defaults and draw counts verified 2026-08-06
(hw_postprocess_cvars.cpp:30,41,47,53,61,99; hw_postprocess.cpp:997; fxaa 2
draws at :380/:392, lens 1 at :350, tonemap 1 at :632, colormap 1 at :565).

Gates the table omits, any of which could confound a future A/B: bloom also
needs the default fixed colormap, no SSAO debug mode, and positive scene
dimensions (:78); tonemap can be forced on by a LEVEL OVERRIDE at gl_tonemap 0
(:610); ssao also returns early on zero dimensions or zero effective strength
(:788).

**colormap is the one that matters and it is not a cvar at all.** A palette
flash — taking damage, picking up an item — makes it run one draw. Pre-5a9b53e1b
that means the screen flipped upside down every time the player got hit. It
survived unnoticed because all testing happens standing still at a pinned
savegame where nothing ever flashes.

TOOLS
================================================================================

- mt_ao_probe [frames] (NEW) — reports the AO composite numerically: the blend
  style actually handed to PSO creation, SceneColor read back before AND after
  the draw with a differing-pixel count, the stencil/clear decisions, whole-frame
  SceneFog stats, and the shader's own alpha derived from Ambient0. Needs
  gl_ssao != 0 and gl_ssao_debug 0.
- mt_capture [frames] (NEW) — programmatic Metal GPU frame capture, no Xcode
  build needed. Needs METAL_CAPTURE_ENABLED=1 on the launch. See
  docs/gpu-capture-protocol.md. Encoder labels are greppable straight out of the
  trace: `strings -n 6 <trace>/capture | grep '^PP '`.
- mt_bloom_dump [frames] — per-level pyramid stats plus PNGs. Dumps only the path
  that ACTUALLY RAN last frame; comparing compute against reference takes two
  launches.
- tools/tonemap_predict.py — predicts the Reinhard capture from the Uncharted2
  one by inverting the curves. Checks tonemap modes by curve RELATION, not by
  difference.
- tools/blobstats.py, pngdiff.py, localize.py, cluster.py as before. Each
  docstring encodes rules that cost a session.

================================================================================
CAPTURE PROTOCOL — screenshots
================================================================================

1. Pin the viewpoint with capspot.zds (MAP51 lantern).
2. ONE LAUNCH PER CONFIGURATION, cvars on the command line. The operator types
   only `screenshot`.
3. Never chain console commands with `;`.
4. The console pauses the game and GetScreenshotBuffer only re-presents, so a
   shot taken with the console open reflects the last frame rendered with it
   CLOSED. macOS Cmd+Shift+4 sidesteps this by capturing the live window.
5. -exec runs before `Init complete.` and +screenshot never fires.
6. +mt_caps on the command line prints viewport numbers from before the first
   frame. The format line is valid; the viewport lines are not.

Determinism: this viewpoint reproduces BIT-EXACTLY for the same elapsed frame
count, and byte-identical pairs have been observed repeatedly. The asymmetry is
the point:
  - BYTE-IDENTICAL is strong: no drift occurred AND the change did nothing.
  - BYTE-DIFFERENT is AMBIGUOUS: equally consistent with a real effect and with
    exposure drift. It needs a same-config control pair before it means
    anything. Measured counterexample: gl_fxaa 0 vs 1 gave +4.12 mean signed
    delta over 39% of the frame, which was exposure, not FXAA.
The frame-count explanation is a plausible mechanism, not a measured result —
no frame-count-controlled artifact is retained.

================================================================================
THE METHOD LESSONS — the expensive ones
================================================================================

- **A DEBUG MODE THAT CHANGES THE PIPELINE IS NOT AN OBSERVATION OF THE
  PIPELINE.** This is the big one from today, and it cost four sessions.
  hw_postprocess.cpp:910 wraps both AO blur passes in `if (gl_ssao_debug < 2)`,
  so every debug mode that displays depth SKIPS the pass that destroys it. Four
  correct debug-mode readings all pointed away from the bug. Before trusting a
  debug view, check what it changes besides the display.
- **A test whose two outcomes look the same is not a test.** Recurred twice
  today: `give PowerInvulnerable` would have passed a colormap test that never
  ran, and a probe reading sampled the darkest pixels — where fog and scene are
  both black and "equal" is guaranteed. Both were caught by asking what the
  negative result would look like.
- **Match the minimum, not the sentence.** Every dead string patch died because
  it spelled out a whole statement and someone edited part of it — including our
  own commits. Anchor on the smallest thing that must be true.
- **Verify the artifact you changed is the one being loaded.** There are TWO
  gzdoom.pk3 files; the engine loads the one in the app bundle. Updating
  build/gzdoom.pk3 alone left the engine running a six-week-old shader and made
  a correct fix measure as a total failure. Also clear the MSL cache.
- **Measure the magnitude, do not eyeball the image.** gl_ssao_debug 3 looked
  "near-black, so depth must be normalised" — the obvious reading, and wrong.
- **A mathematical identity is the strongest available probe.** gl_tonemap 4 is
  sqrt(c*c) == c, which removed shader maths as a variable entirely.
- **Byte-identical captures are ambiguous, ALWAYS.** They mean "perfect
  identity" and "the pass never ran" equally well.
- **State a numeric prediction before looking.** Every real defect on this branch
  was caught this way; several confident readings of the code were not.
- **Check gzdoom.ini before diagnosing a renderer bug.** An entire AO
  investigation once resolved to config.
