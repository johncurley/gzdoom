Verified on screen — STYLEOP_Shadow was 42% too dark on Metal

- STYLEOP_Shadow is enum 8, and vk_renderpass.cpp's renderops[] holds -1 for
  every index above STYLEOP_RevSub, so the reference routes it into the fuzz
  branch: Cout = Cs*Cd + Cd*(1-As). Metal used Zero/SourceAlpha, i.e. Cd*As.
  With hw_sprites.cpp's SetColor(0.2,0.2,0.2,0.44) that is 0.76*Cd against
  0.44*Cd. Fixed in fde91b90b, recorded in 441bb959f.
- The error was alpha-dependent, not constant: reference (1.2-As)*Cd vs Metal
  As*Cd, crossing at As=0.6, and the fog branch scales fuzzalpha DOWN so
  fogged sprites diverged further. Nothing in normal play crosses over.
- Repro at all requires r_drawfuzz 2 (renderstyle.cpp:151-154 converts every
  fuzz style to STYLEOP_Shadow). At the default of 1 this code never runs and
  no stock actor uses STYLE_Shadow, so the bug was real but narrow.
- MEASURED: Metal 0.679 vs Vulkan 0.676 darkening ratio, agreement 0.4%. Had
  the fix not taken Metal would read ~0.39 — a gap ~100x larger.

  The technique matters more than the result. A cross-backend whole-frame
  diff is USELESS for a localized effect: it reported 92.7% of pixels
  differing because the restart forces relocation and the backends differ
  globally anyway. Use an intra-image ratio (effect vs unaffected neighbour
  on the same scanlines, compared between images). Scale-invariant, cancels
  both confounds.

The method lesson — the expensive one

TWO source-reading conclusions about compute bloom were wrong in one session,
against one correct measurement.

- Claimed Metal sums all four bloom levels while the reference composites
  only level0. FALSE. Read bloom_combine_contrib_all without reading its
  caller, which zeroes three of four weights. The all-levels bug was real but
  already fixed 2026-07-30. Retracted in f8fa3ad17.
- Claimed a normalized-UV vs texel-offset unit mismatch. Disproved by
  blur.fp using ivec2 textureOffset.

Both were plausible from the shader alone. Neither survived. **Read every
kernel together with its binding site, and read the comments in the .cpp —
they record prior fixes.**
